# 로컬 검증 기록

확인일: 2026년 10월 19일

## 구현 환경

- Next.js 16.4.2, React 19.3.1, TypeScript 5.9.3
- Node.js 24.19.0
- `next build --webpack` 프로덕션 빌드 성공
- 로컬 실행 URL: http://127.0.0.1:3000/
- SQLite 파일 DB

## 자동 검증

`TEST_BASE_URL=http://127.0.0.1:3000` 설정 후 입력 검증과 실행 중인 Next.js API 통합 검증을 실행했다. Node.js 테스트 러너 집계는 17개 통과, 실패 0개, 건너뜀 0개였다. 집계에는 통합 검증을 묶는 상위 테스트 1개가 포함된다.

다음 내용을 확인했다.

- HttpOnly·SameSite 쿠키 발급과 과제 조회 응답의 캐시 방지
- 과제 등록과 서버 DB 재조회, 수정, 완료 및 미완료 전환과 삭제
- 서로 다른 익명 세션 사이의 목록 분리와 변경·삭제 제한
- 필수값, 문자열 길이, 실제 달력 날짜와 JSON 자료형 검증
- 같은 Origin 허용, 다른 Origin 거부와 사용자 정의 요청 헤더 확인
- 본문 크기 제한과 세션 없는 변경 요청 거부
- SQL·HTML 형태의 입력을 데이터로 저장하며 테이블 유지

## 실제 브라우저 확인

Next.js 화면에서 과제 두 개를 등록하고 한 과제의 설명을 수정했다. 완료 표시 후 집계가 전체 2개, 진행 중 1개, 완료 1개로 바뀌는 것을 확인했다. 페이지를 새로고침한 뒤 두 과제와 수정한 설명, 완료 상태가 유지되는 것도 확인했다. 화면은 `images/main.png`에 저장했다.

실제 Next.js 프로덕션 서버 프로세스를 종료한 뒤 동일한 DB로 다시 실행하고 브라우저를 새로고침했다. 두 과제와 수정한 설명, 완료 상태를 다시 확인했다.

HTML 형태의 과제명을 추가했을 때 화면에 태그가 문자로 나타났으며, 새 img 요소와 JavaScript 대화상자가 없었다. 이 검증용 과제는 확인 대화상자를 거쳐 삭제했고 목록이 다시 두 개로 돌아오는 것을 확인했다. `images/safe-text.png`에 당시 화면을 저장했다.

브라우저의 실제 Origin 헤더를 포함하면 로컬 Host를 잘못 판별하던 부분을 수정했다. 자동 API 검증에도 같은 조건을 포함했다.

## 공개 저장소 확인

2026년 10월 19일 `https://github.com/steve2514/task-note-next` 공개 저장소에 소스와 기말 개선 계획을 업로드했다. GitHub 화면에서 src·tests·docs와 설정 파일을 확인했고, 인증 없는 GitHub API에서도 private:false를 확인했다. Vercel이 해당 저장소를 Next.js로 인식했고 과제 전용 Hobby 프로젝트를 생성했다.

## 아직 검증하지 않은 항목

PostgreSQL 실제 연결, Vercel 공개 배포와 배포 환경의 HTTPS·재배포 후 저장 유지는 DB 연결과 실제 배포 후 확인한다. 로컬 빌드와 검증만으로 배포가 완료되었다고 판단하지 않는다.
